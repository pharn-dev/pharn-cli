# PLAN — pin degit to the measured 3.6.6

**Source finding:** FABLE.md §4.10 (`prompts` brief "Pin degit to the measured 3.6.6").
**Severity:** medium (supply-chain). **Bundle:** PR 3 (security).

## Intent

`package.json` declares `"degit": "^3.6.1"`. Every "measured against `degit@3.6.6`"
claim in `THREAT-MODEL.md` / `LIMITS.md` is written against exactly 3.6.6. Pin the
declaration to `3.6.6` exactly and add a test that mechanically ties the declared
version to the version those documents name, so a bump cannot land without
re-measuring.

## Live-state divergences from the brief (verified 2026-09-08, stated not papered over)

1. **4.11 and 4.01 are already merged** (`b55658e`, PR #121). `tests/skills-version.test.ts`
   already carries both body-cap negative cases and `src/lib/skills-version.ts` already
   streams under a wire-byte cap. Nothing to build for those two siblings; this plan is
   4.10 only.
2. **The drift the finding predicted has ALREADY happened.** `package-lock.json` resolves
   `degit@3.8.0` (not 3.6.6, as the brief and `THREAT-MODEL.md:67` both assert), and
   `node_modules/degit` is 3.8.0. The caret floated. So pinning to `3.6.6` *restores* the
   measured version rather than freezing the status quo, and the `THREAT-MODEL.md:67`
   sentence is currently FALSE on both halves.
3. **`src/lib/repo.ts` no longer contains the literal `degit@3.6.6`.** The `cache: false`
   comment (now line 76) was rewritten by `degit-fetch-boundary-truth` and dropped the
   version, so it makes a measured claim naming no measured version. Re-adding it is a
   comment-only edit — zero fetch-behavior change — and is required by the brief's own
   acceptance criterion.

## Files

- `tests/degit-pin.test.ts` (new) — the self-enforcing pin.
- `package.json` — `"degit": "^3.6.1"` -> `"degit": "3.6.6"`.
- `package-lock.json` — regenerated by `npm install` (3.8.0 -> 3.6.6).
- `THREAT-MODEL.md` — rewrite the range sentence (lines 67-68).
- `src/lib/repo.ts` — re-name `degit@3.6.6` in the `cache: false` comment (comment only).
- `docs/contributing.md` — "bumping degit" note in **Security-sensitive files**.
- `CHANGELOG.md` — `### Security` bullet under `## [Unreleased]`.

## Order (tests first, repo rule)

1. Write `tests/degit-pin.test.ts`; confirm it FAILS against `^3.6.1` + lock 3.8.0.
2. Pin `package.json`, run `npm install`, confirm lock resolves 3.6.6.
3. Re-add the version to the `repo.ts` comment; rewrite the `THREAT-MODEL.md` sentence.
4. `docs/contributing.md` note + `CHANGELOG.md` bullet.
5. `npm run check` + `npm run lint:md` + `npm run build`.

## Guarantee audit (P0)

- **"the declared degit version equals the version the docs name"** -> FLOOR: a vitest
  assertion over four files read off disk (`tests/degit-pin.test.ts`). Deterministic.
- **"the declared version equals the resolved version"** -> FLOOR: same test, comparing
  `package.json` `dependencies.degit` to `package-lock.json`
  `packages["node_modules/degit"].version`.
- **"the prose is still TRUE of those bytes"** -> **ADVISORY, and NOT guaranteed.** The
  test proves the documents *name* the installed version; it can never prove a measured
  claim still holds. Stated in the test's header comment, not implied away.
- **"end users get 3.6.6"** -> ADVISORY. `scripts/build.mjs` leaves degit external and
  npm does not publish lockfiles, so the exact-version *range* is what protects consumers;
  npm honours it, but nothing in this repo verifies a consumer's install tree.

## Out of scope

Bumping degit to 3.7.x/3.8.x (requires re-measuring every THREAT-MODEL §2/§4b bullet);
bundling degit into `dist/`; changing clone strategy (5.3a/5.3b); any
`lib/skills-version.ts` change.
